# Numera Maintainer

## 定位

这是速算程序的项目专属执行 Skill，负责保护训练语义、题目生成、计时、数据归属和同步边界。

优先级：

```text
用户当前明确要求
→ AGENTS.md
→ 本 Skill
→ PROJECT_STATUS.md / 专项当前文档
→ 当前代码与测试
→ README 历史段落 / 旧阶段文档
```

`README.md` 同时包含当前状态和较早历史快照；遇到冲突时，以 `PROJECT_STATUS.md` 顶部“当前正式状态”、当前代码和测试为准。

## 启动协议

开始任何任务前至少读：

1. `AGENTS.md`
2. `PROJECT_STATUS.md`
3. `README.md`
4. 当前任务相关源码与测试

按任务追加：

- 生成器 / 题型：`PROJECT_LOGIC_AUDIT.md` + 对应 generator/tests
- 后续任务：`DEVELOPMENT_PLAN.md`
- 评级：`RATING_STANDARDS.md`
- 历史统计：`HISTORY_REPORTING.md`
- 异步 PK：`PK_ASYNC.md`
- 页面刷新 / hash 路由 / 账号三态 / active 恢复：`NAVIGATION_RECOVERY.md`
- 数据导出：`DATA_EXPORT.md`

## 当前技术基线

当前依赖基线：

```text
Next.js 15
React 19
TypeScript
Vitest + Testing Library + fake-indexeddb
IndexedDB
Supabase Auth / PostgreSQL
Recharts
```

不要按旧“纯本地 MVP / 没有 Supabase”的历史描述工作。

## 产品边界

Numera 是**行测资料分析基础算力训练**，当前核心是列式后的纯计算能力，不自动扩张为完整资料分析公式课程。

新增功能前先判断：

- 它是已有基础算力训练的自然延伸；
- 还是新的学习系统 / 公式课程 / PWA 能力。

后者需要明确产品决策，不能顺手加入。

## 训练数据与身份

固定账号映射为 🐟 / 🐱；训练归属由 Auth 身份决定，不允许 UI 临时选择改写云端归属。

当前数据规则：

- completed：先写 IndexedDB，再尝试幂等同步 Supabase；
- active：只保留当前浏览器，不上传；
- 每个账号和未登录本地范围各自最多一条 active；
- 配对对象历史只读；
- 云端 / 本地同 ID 去重；
- 登录前旧 completed 历史必须由用户明确选择合并或丢弃。

不要为了“同步更完整”擅自上传 active。

## 计时铁律

训练计时只计算真实有效作答时间。

页面隐藏、失焦、锁屏、冻结、`pagehide`、浏览器返回/前进、关闭/跳转及恢复读取都应暂停；BFCache 恢复不能补计离开间隔。

任何会话 / 路由 / storage 修改都必须特别检查：

- 暂存；
- 刷新恢复；
- 前后台切换；
- 重复提交；
- 返回 / 前进；
- 账号切换；
- active 唯一性。

计时正确性优先于“动画顺滑”或实现简洁。

## 题目生成协议

题目生成器是训练质量核心，不在 UI 中复制生成逻辑。

修改任何题型前：

1. 找到正式 `generateSet()` / 结构配额逻辑；
2. 区分单题生成与整组配额；
3. 保留可注入随机源 / ID 工厂和可复现性；
4. 检查所有合法题量，而不是只测 100 题；
5. 验证答案、结构标签、生成器版本与旧记录兼容；
6. 有数学不可行组合时，不能靠静默 fallback 让最终题面偏离配额。

不要仅根据题目“看起来像某结构”修改分类规则；以真实数位、进借位、商结构等定义为准。

## 百化分 / 分数百分

固定高价值题库与两个方向的答题语义属于训练规则，不把它改回普通随机直除题库。

- 分数转百分数与百分数转分数可以是两个一级入口，但底层保持统一题型与各自子模式；
- 百分数转分数按题库对应最简分数判定；
- 消消乐是独立训练体验，不进入普通 TrainingSession、PK、Rating 或普通历史统计。

涉及题库扩展时先读当前题库文件和测试，不从旧说明拼接。

## 评级、趋势与历史

- 新 completed 冻结 rating 快照；
- 评级规则以 `RATING_STANDARDS.md` 为准；
- 趋势按用户 + 题型 + 子模式 + 实际题量隔离；
- 历史统计口径以 `HISTORY_REPORTING.md` 为准；
- 配对对象记录只读；
- 不为了图表方便改变长期统计口径。

## 异步 PK

PK 基于普通 completed 训练发起冻结题组挑战：

- 同题同序；
- 冻结题组不可因为生成器更新而漂移；
- 个人训练长期归档；
- PK 页面只承载当前定义的激励展示；
- 详情按冻结题组完整展示双方作答，缺失项仍保留并标注未作答。

任何 PK 数据、权限、分页和提醒修改先读 `PK_ASYNC.md`。

## UI 修改协议

Numera 是手机优先的训练工具。视觉改动首先服务：

```text
题目可读
输入不误触
计时清楚
关键操作不被键盘 / safe-area 挡住
训练过程尽量少分心
```

当前训练页的重要约束包括：

- `100dvh` 单屏训练布局；
- 数值键盘和主要操作在手机竖屏可直接使用；
- 触控键盘按键保持足够尺寸；
- 长题目在窄屏完整换行；
- 空答案位不要无意义占位；
- 草稿只在内存使用，不识别、不上传、不持久化；
- 结果与历史详情中的草稿入口保持随滚动可达。

使用通用 `ui-ux-pro-max` / `frontend-design` 时，只优化体验与视觉表达，不改题目、判题、统计、计时和同步语义。

## 编码纪律

遵循 `karpathy-guidelines`：

- 只改完成任务必需的部分；
- 不顺手重构相邻生成器；
- 不因为看到旧代码就主动清理兼容层；
- 对业务规则修改先补或调整测试；
- 每个修改都要有可验证成功标准。

## 验证

有意义的代码改动优先执行：

```bash
npm run format:check
npm run typecheck
npm run lint
npm run test
npm run build
```

生成器改动必须增加对应结构 / 配额 / 边界测试；会话与计时改动必须覆盖暂停恢复；同步改动必须覆盖身份、幂等、只读和失败恢复。

无法运行某项时明确说明，不得写“已验证”。
