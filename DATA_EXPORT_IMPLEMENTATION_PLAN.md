# 个人训练数据云端导出 V1：文件级实施计划

## 目标与固定边界

用户登录后，一键从 Supabase 读取当前账号 `owner_id` 对应的全部已同步个人 completed 训练，并在同一次完整读取成功后下载：

- 一份 XLSX：用于筛选、透视和人工/AI 后续复盘；
- 一份 JSON：保留原始云端行、完整 `session_data` 及规范化导出结构，供机器处理与未来迁移/恢复预留。

范围固定：普通训练和 PK 训练统一导出；不读 IndexedDB、不与本地合并、不读 `pk_challenges`，也不导出对手、胜负或挑战信息。App 不生成任何分析结论、图表或训练建议。

旧记录的真实完成时间不猜测；新训练从本功能上线版本开始记录真实 `completedAt`。

### 2. 增加仅个人、完整分页的云端读取 API

| 文件                            | 改动                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/lib/cloud.ts`              | 新增导出专用类型 `CloudCompletedTrainingRow`，包含导出需要的全部表列和原始 `session_data`。新增 `readOwnCompletedTrainingForExport(identityId, onProgress?)`：检查 Supabase 可用，查询 `completed_training_sessions`，显式 `.eq("owner_id", identityId)`，选择完整列，固定排序，并以保守固定页大小循环 `.range(from, to)` 直到短页。每一页都校验/累积结果；任一页报错直接 throw，绝不返回部分结果。它不调用 `readCloudHistory()`、不访问 IndexedDB、也不访问 PK 表。 |
| `src/lib/cloud.test.ts`（新增） | mock Supabase query builder，覆盖：`owner_id` 精确过滤、请求列完整、跨多页拼接、空数据、第二页失败即 reject（不返回第一页）、未配置 Supabase 时失败。还要断言导出 API 不调用 `readPKChallenges` 或本地存储。                                                                                                                                                                                                                                                         |

分页排序使用稳定字段组合。优先按 `real_completed_at`（空值可预测处理）与 `session_id` 排序；实现时依 Supabase/PostgREST 的复合排序能力选择 offset range 或 keyset。无论方案如何，测试必须验证没有“只导出默认前若干行”的截断。

### 3. 建立导出领域模型与纯转换函数

| 文件                                  | 改动                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

| `src/lib/data-export.ts`（同上）      | 训练行：只保留复盘直接相关字段（训练 ID、训练来源 raw/normalized/inferred、题型/子模式、开始/真实完成时间、实际题量、已答/正确数、总用时、冻结等级、基础派生正确率/平均/中位数、版本）。`owner_id`、同步状态、`pkChallengeId`、错误 legacy `completed_at` 等仅留在 JSON 原始归档。                                                                     |
| `src/lib/data-export.ts`（同上）      | 逐题以冻结 `questions` 数组为基准，一题一行；按 `question.id` 找 record，生成 `answer_record_present`。区分“无 record”（空值）和“有 record 但 `user_answer === ""`”；保留 `"0"`。输出题型、子模式、题面、正确/用户答案、是否正确、`accuracyLevel`、有效毫秒、草稿、旧版 restart count、难度、结构、接受范围、常用操作数列，以及 `question_data_json`。 |
| `src/lib/data-export.ts`（同上）      | `training_source_raw` 原样保留（缺失为空）；`training_source_normalized` 为 `pk` 或用于分析的 `normal`；`training_source_inferred` 标记 raw 缺失时的推断。不得静默改写 raw 值。                                                                                                                                                                        |
| `src/lib/data-export.test.ts`（新增） | 用普通、PK、旧缺 `trainingSource`、3% accepted、题组与 records 不一致、空答案、`"0"` 答案、未知 JSON 字段 fixture，验证派生字段、冻结题完整性、来源三字段、操作数展开和原始 JSON 保真。                                                                                                                                                                |

### 4. 生成 XLSX、JSON 与安全下载

| 文件                                        | 改动                                                                                                                                                                                                                                                                       |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `package.json`、`package-lock.json`         | 增加经评估的浏览器端 XLSX 生成依赖（计划采用 `xlsx` / SheetJS Community Edition，实施时锁定版本并核对许可、bundle 大小和浏览器兼容性）。                                                                                                                                   |
| `src/lib/data-export-files.ts`（新增）      | 从 `data-export.ts` 的纯模型生成 JSON Blob 与三 sheet XLSX Blob：`训练记录`、`逐题记录`、`字段说明`。XLSX 只暴露复盘字段，JSON 保留技术/原始数据。应用安全文本转义，防止以 `=`, `+`, `-`, `@` 开头的题面或答案成为 Excel 公式。UUID、题目 ID、答案、版本号强制文本单元格。 |
| `src/lib/data-export-files.ts`（同上）      | 定义文件名：`speed-math-personal-training-export_YYYY-MM-DDTHH-mm-ss+08-00.xlsx/json`。时间同时提供 Unix 毫秒和 ISO 字符串；时长基础单位为毫秒，正确率为 0–1 数值并做 Excel 百分比显示；数组在 XLSX 以 JSON 文本表达；不适用为真正空值。                                   |
| `src/lib/data-export-files.test.ts`（新增） | 覆盖 JSON 的 schema/未知字段保存、XLSX 三工作表、列顺序、中文名与英文字段说明、公式防护、ID 文本、空值/零/空字符串语义、日期/时长/百分比格式。用生成器库反读工作簿核验。                                                                                                   |

两个文件必须由同一个已完成的云端行数组生成。生成任一文件失败则整体视为导出失败，撤销临时 URL，不提示成功。

## 必测验收矩阵

1. 未登录、Supabase 未配置、无有效 profile：不生成文件。
2. RLS 允许读取配对对象时：导出专用请求仍只返回 `owner_id === 当前账号 UUID`。
3. 普通与 PK 个人会话都出现一次；不请求 `pk_challenges`，XLSX 仅显示来源。
4. 多页与最后短页；任一中间页失败时零下载。
5. 旧会话没有 `completedAt`/`trainingSource`/新结构字段：完成时间为空、来源 raw 为空且 inference 有标记、未知字段仍留在 JSON 原始行。
6. 新会话：真实完成时间准确、开始与完成明确区分；不把 legacy `completed_at` 放入 XLSX。
7. 3% 估算题：`exact`、`accepted`、`wrong` 和接受范围均完整导出。
8. 每个冻结题都有一行；没有作答 record、空字符串答案和 `"0"` 答案互不混淆。
9. CSV 公式形式的题面/答案不会成为 Excel 公式；UUID/ID 不被转为数值或科学计数法。
10. 合成数万逐题记录：有分页进度，生成完整双文件，内存/交互可接受。

## 实施完成的定义

- 已部署真实完成时间 migration，并验证新记录可保存、旧记录不回填。
- 导出只读 Supabase 个人 completed 数据，并完整分页；失败不生成部分文件。
- 每次成功导出生成范围完全一致的 XLSX 与 JSON。
- XLSX 含 `训练记录`、`逐题记录`、`字段说明`；JSON 同时保留原始云端数据和稳定规范结构。
- 不引入本地数据、对方数据、PK challenge 查询、App 内分析或数据导入/恢复承诺。
