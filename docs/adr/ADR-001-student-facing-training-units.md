# ADR-001：第一层能力与学生训练单位

- **状态**：Accepted（2026-09-11修订）
- **范围**：第一层纯计算能力、学生专项入口、Mastery边界、方法训练交互

## 背景

项目曾把纯计算层拆成160个叶子并全部接成 `skill_drill`。这一版本完成了大量生成器、步骤计时和结构化输入基础设施，但后续产品审查确认：

> **“程序能诊断到多细”不等于“产品就应该建立多少正式能力”。**

160叶子版本没有真实训练数据，真正需要兼容的是经典版本历史记录。因此160个叶子不再作为新架构的正式Mastery约束。

## 决策1：A层正式能力只保留8个

当前 canonical A ability：

- `A-ADD-01` 2～3位加法
- `A-SUB-01` 2～3位减法
- `A-COM-01` 近邻小差值
- `A-MUL-01` 正向乘法口诀
- `A-MUL-02` 逆向乘法口诀
- `A-MUL-03` 两位数×一位数
- `A-FRA-01` 高频分数↔百分数固定映射
- `A-PCT-01` 基础百分比取值

准入原则：

> **只有“单独练它能够明显提升上层表现”的底层动作，才值得成为A层正式能力。**

进位、借位、负结果、具体百分比锚点、特殊乘数等优先作为 `preset / variant / structure_tags`，不建立新的Mastery。

## 决策2：B只作为方法/解析参考

B不建立长期独立Mastery。凑整、拆分、选基准、百分比拆分、特殊倒数转换等仅用于：

- 方法训练关键步骤；
- 解题解析；
- 方法标签；
- 诊断标签。

## 决策3：C当前暂停开发

当前只保留三个完整纯计算任务候选：

- 乘法综合；
- 除法综合；
- 分数比较。

加减综合因与A重复删除；抽象复合算式因应从第二层真实资料分析计算模型中拆解而删除。

本轮只开发A层。

## 决策4：方法训练与综合训练长期并列

> **方法训练把“方法”显式化；综合训练把“方法选择”交还给用户。**

“方法”和“过程”视为同一件事：选择某个方法训练时，界面只收集该方法真正值得显式填写的关键步骤。

不存在强制的“学习→引导→独立→综合”生命周期。用户任何时候都可以选择方法训练或综合训练，两种都需要讲解。

只看到最终答案时，不允许推断用户未显式提交的脑内方法。

## 决策5：数据建模分层

统一目标：

`ability_id → preset / variant → structure_tags → generator_params`

当前程序可继续使用 `skill_id` 字段承载8个canonical A ID，以降低迁移风险。旧160叶子注册表可暂时保留为技术遗留，不再是产品事实源。

## 决策6：经典历史数据保持原义

- 经典记录继续可读、可展示、可导出；
- 不批量重写；
- 不为旧记录猜新 `ability_id`；
- 若未来做事后映射，必须明确标记为 derived / post-hoc。

## 当前实现要求

A层8能力应做到：

- `A-COM-01 / A-MUL-01 / A-MUL-02 / A-FRA-01`：4选1，首次点击即提交；
- `A-ADD-01 / A-SUB-01 / A-MUL-03 / A-PCT-01`：数字输入；
- 加减限定2～3位；
- 减法允许正、负、0；
- `A-FRA-01` 双向固定映射统一一个能力；
- `A-PCT-01` 统一12个基础百分比锚点；
- 旧微叶子不再出现在正式A专项选择器中。
